## 按此顺序手测

1. 安装 x86 FPK，无需填写部署参数。打开入口；确认 HTTP、静态资源和 WebSocket 都位于 `/app/remote-desktop`。Socket 默认由包用户/组以 0660 创建；不要改成 777。
2. 用两个 NAS 用户分别进入应用；A 新建连接和凭据，B 不应看到。管理员也不应自动看到他人的私有对象。尝试绕过 Socket 入口和自报 `X-Trim-*`，必须不能获得其他用户权限。
3. Windows 准备：支持 RDP 主机的系统，开启远程桌面并允许目标账号，有效的远端证书（自签名证书可在应用内核对并确认），NAS 到目标 3389 可达。创建 RDP 连接，用本次凭据及保存凭据各试一次。端口探测只说明 TCP 可达，不代表认证成功。
4. 错密码、拒绝登录、目标断网、首次自签名、证书变化、撤销信任、过期/名称不符证书分别验证。确认后自动继续连接；再次连接相同证书不应重复提示。不得自动降级信任；记录实际错误分类。桌面尚无有效显示时应保持“连接中”，最多 30 秒后结束。
5. Mac 准备：屏幕共享或有效的远程管理 VNC 服务，VNC 查看器密码，5900 可达。分别记录系统版本、LibVNCClient 和认证模式。首版不要选择 ARD 账号认证；不会把输入用户名视作支持 ARD。
6. 对两种协议验证点击、拖动、滚动、按键、中英文及 emoji；按住 Ctrl/Alt/Command 后切换标签和窗口，再返回，确认无粘键。全屏和适应窗口分别在 fnOS iframe 与独立标签页测试。
7. 显式启用文本剪贴板后，用两个不同类型的目标应用测试浏览器到远端和远端到浏览器：英文、中文、emoji、换行。逐项记录，不把一个组合通过推广到全部 Mac。未通过时关闭该连接的剪贴板。
8. 并发打开超过每人 2 / 应用 4 个会话，必须明确拒绝超额。连接中取消、关闭标签、断网、刷新及 guacd 退出后，界面状态必须收敛且释放配额。重试建立新会话。
9. 重复启动 / 停止 / status、NAS 重启、引擎 Socket 路径被占用、磁盘满、Socket 权限不足。验证不会误连其他 guacd；故障不得用宽泛 pkill 清进程。
10. 升级前备份，验证旧凭据可解密；模拟失败迁移和恢复；回滚程序时配套恢复数据与密钥。卸载前先在应用目录外备份，分别验证保留后重装、主动清理以及目录归属异常时中止清理。
11. 对空闲桌面、文本编辑、滚动和接近配额的多会话运行一个工作时段。记录 Go/guacd RSS、CPU、FD、连接耗时与输入反馈，反复断开应回归合理基线。NAS 注销联动当前未接入，不能宣称立即断开已有长连接。
12. 检查日志、SQLite、浏览器存储和诊断中无明文密码、剪贴板或按键；网关日志必须自行核对 `ticket` 查询参数是否脱敏。Go 不记录 URL 不等于网关已完成脱敏。

每次记录：fnOS 版本、CPU/内存、包 SHA-256、浏览器版本、目标系统版本、认证模式、原生依赖版本、网络条件、通过/失败与实际日志。先完成需求 P0 三项（网关、干净环境原生依赖、Mac 认证/剪贴板边界），再确定支持范围和最低系统版本。

## 动态显示尺寸

“适应窗口”允许等比例放大和缩小。RDP 使用 `resize-method=display-update`，在连接就绪、可用画布尺寸变化及进入/退出全屏时发送 `size`；连续变化防抖 200 ms，相同尺寸不重复发送。隐藏标签页、断开的会话不请求更新；选择固定百分比时保留远端分辨率，只调整本地缩放。VNC 只调整本地缩放。

初始分辨率与后续更新均按浏览器 CSS 像素计算，尺寸限制 320×200 至 4096×2160，超出上限时按比例约束。默认 DPI 为 96。设备像素比不再倍增远程分辨率，避免 Windows 未同步调整界面缩放时出现小字、小图标和小任务栏。底层动态显示通道的 DesktopScaleFactor/DeviceScaleFactor 没有随 Retina 密度调整，因此不能把高像素分辨率等同于正常大小的高密度显示。旧服务器不支持显示更新时保持等比例显示，不自动断开重连。机制参考 [Guacamole 1.6 配置文档](https://guacamole.apache.org/doc/gug/configuring-guacamole.html#rdp-display-settings)。

本地浏览器回归（使用模拟 WebSocket，不需要访问实际远程电脑）：

```bash
# 终端一
npm --prefix web run dev -- --port 15173
# 终端二
cd web
RD_DISPLAY_QA=1 npx playwright test display-resize.spec.ts
```

验证普通/2 倍密度屏幕上的等比例放大、窗口变化、固定缩放、全屏进出、重复请求抑制及断开停止更新。Go 测试验证尺寸边界、RDP 参数以及 WebSocket 到上游的 size 转发。这些验证不等同于 Windows RDP 实机验收；更新安装后需新建会话检查远端分辨率与文字清晰度。

## 系统文字剪贴板双向同步

新连接默认启用文本剪贴板。在远程页面的“会话设置 → 剪贴板”中可以调整，点击“重新连接并应用”后生效。聚焦远程桌面或从其他应用返回时尝试读取本机文字并发送；直接在画布按 Ctrl+V / Command+V 或 Shift+Insert 时，通过浏览器 paste 事件取得文字，完成 Guacamole 剪贴板传输后再向远端发送粘贴快捷键。RDP 使用 Ctrl+V，Mac VNC 使用 Command+V。在 Mac 本机使用 Command+C/X 操作 RDP 时转换为远端 Ctrl+C/X。

当前正在操作的远程画布收到远端复制文字时，尝试写入本机系统剪贴板。隐藏、后台、失去焦点的会话不自动改写系统剪贴板，收到的文字仍保留在对应会话的面板中。读取失败、写入失败和超长文字状态显示在“剪贴板”按钮提示和面板内，不新增页面横幅。面板保留“发送到远端”和“复制到本机”；不支持自动写入时，可点击后者或选中文字手动复制。

自动系统剪贴板依赖浏览器安全上下文、站点剪贴板权限，以及内嵌宿主的权限策略。HTTPS 生产入口更适合启用自动同步；普通 HTTP 下仍可尝试浏览器原生粘贴事件和手动面板。Safari/Firefox 可能要求每次用户手势，不能承诺所有浏览器都无提示同步。参考 [Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)。仅处理 text/plain，不处理图片、文件或富文本。发送前按网关 base64 总载荷上限检查，超长文字保留在面板并提示分段复制，不发送导致连接断开的指令。

本地验证：运行 Vite 15173 后，在 web 目录执行 `RD_DISPLAY_QA=1 npx playwright test clipboard-sync.spec.ts`。测试覆盖真实浏览器系统剪贴板读写、原生粘贴顺序、权限拒绝、手动发送、禁用隔离、后台隔离、VNC 快捷键和超长文字保护。远端使用模拟 Guacamole 协议，不能代替真实 Windows/Mac 兼容性验收。

## Mac 本机修饰键与 Windows

Mac 本机连接 RDP 时，默认使用“Control / Command → Ctrl”，将浏览器上报的左右 Control、Command/Meta 转为对应的远端 Ctrl，覆盖全部组合键，不仅限于剪贴板操作。用户在 macOS 中互换 Control 与 Command 后，上报为 Meta 的实体 Control 也不会再误触远端 Win。保留工具栏 Win 按钮发送真正 Win 键；“键盘映射 → 原样传递”可恢复原始键值。当前版本对所有客户端开放键盘映射，按 RDP / VNC 分别保存本机浏览器选择。切换模式、失焦或特殊键操作前释放已按下修饰键，并合并同时按住的相同远端修饰键，避免提前释放。非 Mac 本机默认原样传递；远端 Mac VNC 保留 Command 语义。

浏览器回归模拟了 key=Meta / code=ControlLeft 与 key=Control / code=MetaLeft 的系统互换事件，并检查全选、撤销、保存、复制以及原样模式和工具栏 Win 的协议按键。真实 macOS 系统重映射、OS 截获的全局快捷键、Windows/Mac 实机行为仍需安装后验收。

### 用户可选键盘映射

远程工具栏“键盘映射”提供三种模式：

- 原样传递：使用浏览器上报的 Control、Command/Win 键值。
- Command / Win → Ctrl：保留 Control，将 Command/Win 也转为 Ctrl。
- Ctrl ↔ Command / Win：互换两类修饰键；远端 Windows 的 Control 转为 Win，远端 Mac 的 Control 转为 Command。

左右键分别映射，切换前释放旧的按键状态。RDP 和 VNC 分别记住本机浏览器选择，刷新或重新连接后恢复；禁止站点存储时只在当前会话生效。没有保存选择时，Mac 本机连接 RDP 默认使用 Command/Win → Ctrl，其余默认原样传递。工具栏 Win/Command 按钮始终表示远端真实特殊键。系统剪贴板的原生粘贴动作仍按目标系统的 Ctrl+V / Command+V 发送。

## 工作区与悬浮桌面工具栏

页面上下外部留白为 0；侧栏顶部提供“收起侧栏”，工作区左上角保留“展开侧栏”。会话标签栏作为顶部独立的一行保留，远程画布使用其下的剩余高度；透明底色工具栏绝对定位在远程画布内，不占布局高度。工具面板默认关闭，点击圆形悬浮工具按钮展开，面板紧贴远程桌面顶部；点击桌面或 Esc 关闭，连接正常且控件未聚焦时离开面板后可自动收起。正常连接不再显示常驻提示小字，仅异常时显示必要信息。菜单操作和键盘聚焦期间保持显示，连接错误或断开时自动显示。收起的控件不可点击，不会把工具栏点击穿透给远端；圆形入口始终保留，可拖动位置、闲置后淡化，悬停或聚焦恢复；本机浏览器记住归一化位置，窗口缩放及全屏切换后限制在可见区域，拖动不转发到远端也不展开面板。全屏内同样可展开工具栏、断开或关闭会话。

浏览器模拟验证画布从 y=0 开始覆盖整个桌面视口、工具栏显示/隐藏前后尺寸相同；本地 Go 页面验证侧栏收起和恢复、工作区上下贴边。真实 fnOS 宿主和 Windows/Mac 远端画面需升级后确认。

### 分辨率确认与延迟显示通道

初始分辨率按实际工作区扣除标签栏高度测量；尚无会话标签时在不占布局的隐藏测量节点读取真实标签栏高度，测量后移除。RDP 初始 width、height、dpi 显式使用会话协商值，动态 size 使用同一像素口径。浏览器不再将“请求已发送”视为“远端已应用”：实际返回尺寸与请求尺寸相差超过 4 像素时，每 1.5 秒重试，每轮最多 5 次；收到新的桌面尺寸、窗口变化或重新显示会话时再核对。确认匹配后停止重试。隐藏、断开的会话不继续后台重试。

新增模拟延迟响应测试：首次尺寸请求不生效，第二次才返回新尺寸；确认标签栏与桌面不重叠，画面最终覆盖标签栏下方整个画布，确认后不再重发。该测试不代替实际 Windows 显示通道验收；远端不支持调整或用户选用固定百分比时，宽高比不一致仍可能有黑边，不通过拉伸或裁切伪装填满。

## 用户可选显示缩放

RDP 自动分辨率模式中的“内容大小”独立于“画面适配”。支持 50/75/100/125/150/175/200%，默认 100%，通过请求“可用画布尺寸 ÷ 选择比例”的远程分辨率调整文字和图标的可见大小；比例越小内容越多，比例越大字号越大。保留宽高比，受 320×200 至 4096×2160 的远端尺寸范围限制，极小窗口下实际比例会被限制。选择保存在本机浏览器的 RDP 偏好中，初始握手、刷新和重新连接均使用同一值；存储被禁用时当前会话仍可切换。切换后保持画面适配选择并发送新分辨率，确认与重试逻辑继续生效，不要求重新连接。

此功能不是 Windows 系统 DPI/缩放控制。96 DPI 保持不变，以避免动态显示通道不支持同步 UI 缩放而再次出现默认小字；更多内容、字号和像素锐度存在取舍。独立的画面缩放只放大/缩小已收到的画面，新增 125/150/200% 比例用于需要手动放大的场景；VNC 不承诺远端分辨率更新，可使用该画面缩放并滚动查看。

浏览器模拟测试覆盖显示缩放对应的实际请求尺寸、填满画布、刷新后保存、恢复 100%，以及普通/Retina 屏和全屏尺寸变化。实际 Windows/Mac 字体与清晰度仍需安装后检查。

## 分组会话设置

通过悬浮入口打开工具条，再点“会话设置”查看显示与键盘分组。画面适配沿用本地缩放；内容大小的小／标准／大分别为 75%／100%／150%，完整比例仍位于“更多比例”。按键映射采用清晰的名称，内部映射值和已保存偏好不变；特殊键在同一面板内发送。顶部标签 × 负责关闭会话，主工具条保留断开和重连。设置与剪贴板互斥展开，关闭不会丢失面板文字。

窄屏将剪贴板、断开收为有可访问名称的图标；设置展开时暂时隐藏悬浮入口，面板自身保留关闭按钮。分组面板不占远程画布空间，不修改原始像素坐标处理。设计比对见项目根目录 design-qa.md；预览 HTML/TS 位于 web/tests，仅用于本地模拟，不进入生产 web/dist。

## 自动与固定分辨率（0.1.22）

RDP 在显示分组可选自动跟随窗口或固定 1280×720、1600×900、1920×1080、1920×1200、2560×1440、3840×2160。自动模式按窗口与内容大小计算请求；固定模式直接请求选定像素尺寸，禁用小／标准／大和更多比例，既不清除偏好，也不应用该比例。切回自动立即恢复原内容大小。

画面适配始终可用、与分辨率独立：切换适应窗口、原始尺寸或手动缩放不修改固定值；窗口和全屏变化在自动模式更新尺寸，在固定模式只改变本地显示比例。原始尺寸和手动缩放保留左上角起点，可通过滚动查看更大的远端画面。实际分辨率只读取 Guacamole 返回尺寸，远端未应用或拒绝请求时继续显示实际旧值，并保留有限重试。

分辨率选择保存于本机浏览器的 RDP 偏好，初始握手和动态更新使用同一值；非法存储值回退自动，VNC 不提供无协议支持的固定分辨率功能。浏览器协议模拟覆盖固定尺寸、禁用内容控件、独立画面适配、窗口／全屏不改写固定值、刷新恢复、实际尺寸确认和切回自动恢复偏好；Windows 真机仍需安装后确认。

## 0.1.27 VNC 跨平台自动目标

前后端已取消 VNC=macOS 的强制绑定，VNC 的目标系统字段统一为 auto，协议仍为 VNC 密码认证；不开放 ARD 账户认证。标准 VNC 初始化信息无法普遍提供操作系统/版本，界面在无可靠来源时显示“系统未识别”，不基于桌面名称猜测。Windows/Linux VNC 服务以及 macOS 屏幕共享应分别实测，模拟引擎只能验证连接通道、画面、输入事件与状态逻辑，不能当作真实服务端兼容证据。

新自动目标的远端粘贴默认为 Ctrl+V；连接 Mac 时可在“会话设置 → 远端粘贴快捷键”选择 Command+V，按连接记住。旧的 Mac 目标仍默认 Command+V；首次编辑保存为自动目标后，如需要请明确选择快捷键。

## VNC 密码认证与 macOS 多认证方式兼容

应用只收集 VNC 密码，不收集 ARD 用户名。原生 Guacamole VNC 插件不再注册通用账号凭据回调，由 LibVNCClient 跳过需要账号的认证类型；保留密码回调及库本身的密码/TLS 协商。否则 macOS 同时提供 Apple 账号认证（30）和 VNC 密码认证（2）时，库优先选择账号认证，随后 Guacamole 等待本应用不提供的用户名，表现为等待画面后超时。

原生构建会运行 `scripts/native/test-vnc-password-auth.py`，使用真实随包 guacd/LibVNCClient 与本地合成 RFB 服务验证：`[30, 2]` 和 `[2]` 均通过密码认证流程接收画面；`[30]` 明确失败，不等待账号输入。测试密码及画面均为合成数据；不代表已完成 NAS 到真实 Mac 的密码登录验收。

## Windows RDP 会话之间复制文件

新建的 RDP 连接默认启用跨会话文件剪贴板。已有连接沿用已保存的选择，可在远程页面的“会话设置 → 剪贴板”中调整，再点击“重新连接并应用”。在同一工作区的源会话中选中文件按 Ctrl+C，切换到目标会话的资源管理器文件夹后按 Ctrl+V。可以连续多选普通文件，单次最多 64 个、总计 256 MiB。文件夹可先压缩为一个文件。两台 Windows 均需允许 RDP 文件剪贴板重定向。文本剪贴板开关独立。

复制期间请保持源会话连接。文件临时存放在 NAS 应用的用户专属目录中，完成读取后目标会话按需读取各段内容。复制新的内容或断开源会话会清理旧快照，应用重启时清理异常退出留下的快照。浏览器只交换临时标识。
